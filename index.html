Selected architecture projects

Complex problems, delivered

01

Bank-wide container platform re-platforming: 11 business-critical applications

Red Hat OpenShift → Alauda Container Platform · Gateway API · Kong · JFrog · Elastic 8.x

Eleven business-critical applications (internet and mobile banking, digital wallet, onboarding, card tokenisation, fraud detection, teller, workflow and payment aggregation) had to change platforms with no customer impact. At the same time ingress, API management, image registries and logging were reaching end of support, so the whole supporting stack had to be redesigned, not just lifted.

  • Owned the programme end to end: application inventory, target architecture, migration waves, team mobilisation, cutover, operational handover and decommissioning.
  • Renewed the supporting stack: Gateway API in place of Routes; Kong and Envoy Gateway in place of 3scale and RHSSO; centralised JFrog Artifactory with Xray scanning; Elastic Stack 8.x.
  • Resolved TLS trust-chain, DNS, scheduling, session-persistence and gateway-timeout issues; proved readiness through stress testing and CSO assurance (penetration testing, kube-bench).
  • Applied LLMs to migration mapping and artefact drafting, with every output expert-reviewed.

All 11 applications migrated; OpenShift 3 and 4 decommissioned; reusable migration playbooks, per-application issue records and management reporting handed to application, security, architecture and operations teams.

02

Monolith-to-microservices modernisation of banking applications

OpenShift · Kubernetes · AWS · API gateway · GitOps

Monolithic banking workloads changed slowly, scaled only as a whole, and were tightly coupled to core banking interfaces and shared data, so every release carried risk for customer-facing channels.

  • Defined service boundaries by business capability and moved functionality out incrementally behind an API gateway (strangler pattern), keeping channels live throughout.
  • Designed API-led integration to core banking and surrounding systems; externalised configuration, secrets and session state; gave each service its own pipeline and GitOps deployment.
  • Managed shared-database coupling, transaction integrity with the core, session persistence and cross-service observability; guided country teams across Africa onto the platform.

Independently deployable, horizontally scalable services on standard pipelines, security controls and monitoring.

03

Multi-data-centre OpenShift platform for Absa Regional Operations

OpenShift 3 and 4 · VMware · Huawei HyperFusion · RHEL / CoreOS

Regional banking applications needed a highly available, secure container platform spanning several data centres and two virtualisation stacks.

  • Designed and set up OpenShift Container Platform clusters across multiple data centres on VMware and Huawei HyperFusion. Led RHEL and CoreOS builds and expert cluster administration on OpenShift 3 and 4.
  • Integrated workloads migrated to AWS and Azure with the OpenShift platform for hybrid operation.

A production platform built for high availability and security, used to onboard applications from across Africa.

04

Secure, highly available AWS and hybrid-cloud architecture

AWS · Azure · Terraform · CloudFormation · Well-Architected

On-premises banking applications needed resilient, compliant cloud hosting and a faster, consistent way to provision it.

  • Architected fault-tolerant AWS solutions (EC2, Lambda, S3, RDS, VPC, CloudFront, Auto Scaling, Multi-AZ) aligned to ISO 27001 and SOC 2.
  • Led Infrastructure as Code in Terraform and CloudFormation, reducing provisioning time and drift; orchestrated delivery with CodePipeline, CodeBuild and CodeDeploy.
  • Ran AWS Well-Architected reviews to close security gaps and optimise cost, performance and reliability; monitored with CloudWatch, X-Ray and Prometheus. Migrated on-premises applications to AWS and Azure.

Repeatable, code-defined, reviewed cloud environments running alongside the on-premises platform.

05

Enterprise automation and high availability at MTN

Red Hat Satellite · Ansible Tower · Insights · Red Hat HA · Kubernetes

A large Linux estate across on-premises, DMZ, Azure and cloud zones was patched and configured by hand, and a mission-critical customer application needed higher availability.

  • Built the Satellite capsule and Ansible Tower automation estate across on-premises, DMZ and Azure, with Insights-driven patching and a hardening baseline to MTN standards.
  • Delivered Red Hat HA clustering for the Single View customer application and Kubernetes clusters with Calico, Flannel and Weave networking.

Automated, standardised operations across zones and a resilient platform for a mission-critical application.
