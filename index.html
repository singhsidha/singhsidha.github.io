Architecting the platforms that banks run on

Enterprise solutions architect and platform engineering leader with 18+ years in technology and nearly 10 years architecting, building and running the platforms of tier-one African banks. Selected architecture projects

Complex problems, delivered

01

Bank-wide container platform re-platforming: 11 business-critical applications

Red Hat OpenShift → Alauda Container Platform · Gateway API · Kong · JFrog · Elastic 8.x

Eleven business-critical applications (internet and mobile banking, digital wallet, onboarding, card tokenisation, fraud detection, teller, workflow and payment aggregation) had to change platforms with no customer impact. At the same time ingress, API management, image registries and logging were reaching end of support, so the whole supporting stack had to be redesigned, not just lifted.

  • Owned the programme end to end: application inventory, target architecture, migration waves, team mobilisation, cutover, operational handover and decommissioning.
  • Replaced OpenShift Routes with a Gateway API architecture (HTTPRoute, TLSRoute, TCPRoute) and re-implemented ingress and gateway services.
  • Replaced Red Hat 3scale and RHSSO with Kong and Envoy Gateway; moved from internal registries to a centralised, highly available JFrog Artifactory with per-application repositories and Xray image scanning; upgraded Elastic Stack to 8.x.
  • Resolved the hard engineering problems: TLS certificate trust chains to downstream systems, CoreDNS and DNS resolution, pod scheduling and node capacity, session persistence and gateway timeouts, including complex scheduling and DNS issues on a high-volume application.
  • Proved readiness with performance and stress testing and end-to-end checks, and prepared CSO assurance evidence on integrations, registry strategy, penetration testing and kube-bench hardening.
  • Used LLMs to map OpenShift constructs to Alauda, accelerate inventory analysis and draft configuration, with every AI-assisted output expert-reviewed and tested before production.

All 11 applications migrated; OpenShift 3 and 4 decommissioned; reusable migration playbooks, per-application issue records and management reporting handed to application, security, architecture and operations teams.

02

Monolith-to-microservices modernisation of banking applications

OpenShift · Kubernetes · AWS · API gateway · GitOps

Monolithic banking workloads changed slowly, scaled only as a whole, and were tightly coupled to core banking interfaces and shared data, so every release carried risk for customer-facing channels.

  • Defined service boundaries by business capability and moved functionality out incrementally behind an API gateway (strangler pattern), keeping channels live throughout.
  • Designed API-led integration to core banking and surrounding systems; externalised configuration, secrets and session state; gave each service its own pipeline and GitOps deployment.
  • Worked through shared-database coupling, transaction integrity with the core, session persistence, service-to-service TLS and observability across many services.
  • Guided country teams across Africa in containerising their applications and onboarding them to the shared OpenShift platform.

Independently deployable, horizontally scalable services on standard pipelines, security controls and monitoring.

Both digital channels on OpenShift 4; declarative, auditable GitOps delivery adopted as standard.
